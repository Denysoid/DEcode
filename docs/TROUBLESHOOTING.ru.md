# Решение проблем DEcode

[English](TROUBLESHOOTING.md) · [Документация](README.ru.md) · [Установка](INSTALLATION.ru.md) · [Настройка](CONFIGURATION.ru.md)

Начинайте диагностику с точного текста ошибки, точного запущенного файла и пути активной конфигурации. Не публикуйте в issue API-ключи, authorization headers, приватные prompts, код закрытого репозитория, имя пользователя или чувствительные пути.

## Окно открывается и сразу закрывается

DEcode — терминальное приложение. Консоль, открытая двойным щелчком, закрывается сразу после завершения процесса и скрывает ошибку конфигурации. Запускайте файл из уже открытого терминала:

```bat
cd /d D:\path\to\DEcode
target\release\decode.exe --workspace "D:\path\to\project"
```

```powershell
Set-Location D:\path\to\DEcode
& .\target\release\decode.exe --workspace "D:\path\to\project"
```

Не закрывайте терминал и прочитайте последнюю ошибку. Права администратора обычно не нужны; повышенный запуск может выбрать другой профиль пользователя, keyring, конфиг и каталог сессий.

## Для `--workspace` требуется значение

`--workspace` — не переключатель. Передайте существующий каталог:

```text
decode --workspace /абсолютный/путь/к/проекту
```

Путь с пробелами заключайте в кавычки. Путь к файлу не принимается.

## EXE и `cargo run` показывают разные настройки или сессии

Сначала проверьте, какой бинарник запускается:

```bat
where decode
```

```powershell
Get-Command decode -All
```

```bash
type -a decode
```

Затем запускайте оба варианта с одинаковыми явными путями:

```text
decode --config /абсолютный/config.toml --workspace /абсолютный/project
```

Проверьте `agent.session_dir` в этом конфиге. Разные бинарники, пользователи ОС, значения `--config` или каталоги сессий закономерно показывают разные настройки и списки сессий. После изменения исходников пересоберите или переустановите программу:

```bash
cargo build --locked --release
cargo install --locked --path . --force
```

При сравнении keyring и пользовательских данных не запускайте одну копию с повышенными правами, а другую — от обычного пользователя.

## `invalid api.responses_url: relative URL without a base`

Настроенный endpoint пустой или относительный. Укажите абсолютный HTTPS URL с host либо удалите пользовательское поле и используйте стандартный endpoint провайдера. Для Azure настройте ровно один вариант:

- полный `responses_url` с нужным маршрутом Responses;
- `azure_base_url` вместе с правильным deployment.

Не задавайте оба одновременно. Проверьте файл, реально выбранный через `--config`: изменение другого `config.toml` не влияет на процесс.

## HTTP 404 `Resource not found`

Соединение с сервером установлено, но маршрут или deployment не найден. Проверьте:

- выбранного провайдера;
- hostname ресурса и регион;
- имя deployment или модели с учётом регистра;
- Azure base URL либо полный Responses URL;
- доступ аккаунта к этому API-маршруту;
- изменение адреса прокси-сервером.

Правильный API-ключ не доказывает существование deployment или маршрута. После исправления endpoint проверьте минимальный запрос только с текстом.

## `This model is not supported by Responses API`

Выбранные модель и endpoint не поддерживают протокол Responses. Выберите Responses-совместимую модель/deployment либо настройте адаптер провайдера, который реализует настоящий протокол модели. Увеличение контекста, повтор запроса или смена вложения не устраняют несовпадение протоколов.

## Ошибка авторизации

Выполните `decode --help` и проверьте выбранного провайдера. Затем проверяйте только соответствующую переменную из [таблицы ключей](CONFIGURATION.ru.md#учётные-данные). Частые причины:

- ключ относится к другому провайдеру, ресурсу, региону или deployment;
- терминал открыт до установки переменной окружения;
- `--env-file` не передан или указывает внутрь workspace;
- выбран устаревший keyring entry;
- неверны системное время, AWS profile или region;
- корпоративный proxy удаляет authorization headers.

Не вставляйте ключ в лог или issue. Ответы `401` и `403` автоматически не повторяются: retry не исправляет учётные данные или policy.

## Контекст резко уменьшается или запрос отклоняется

Различайте три значения:

- суммарные токены сессии, которые только растут;
- токены последнего запроса к провайдеру;
- выбранный бюджет контекста одного запроса.

Сжатие намеренно уменьшает второе значение, а не общий ledger. DEcode добавляет в чат отметку о сжатии и сохраняет начальную задачу вместе с новейшей полной причинной группой. Если одна обязательная группа превышает выбранный бюджет, запрос отклоняется вместо удаления результатов инструментов или недавних инструкций.

Что делать:

1. проверьте реальное документированное окно модели;
2. выберите бюджет не больше этого окна;
3. уберите необязательные большие вложения из нового хода;
4. завершите текущую причинную операцию до начала несвязанной задачи;
5. создайте fork или новую сессию для отдельной цели.

Увеличение `max_context_budget` до выдуманного значения не расширяет возможности провайдера. Если числа UI превышают бюджет, проверьте, не показывается ли суммарный usage вместо размера текущего запроса.

## Сессия возвращается к неожиданному бюджету контекста

Каждая существующая сессия хранит собственный выбранный бюджет. Последнее явное изменение также становится значением по умолчанию для новых сессий. Проверьте, что открыты нужная сессия и тот же каталог сессий. Если значение всё равно меняется после повторного открытия одной и той же сессии, сохраните шаги и очищенные от приватных данных metadata сессии и сообщите о баге.

## Вложение отображается как путь, а не файл

До отправки успешно прикреплённый файл показан chip с именем, типом и размером. Если путь остался обычным текстом composer, откройте `@` либо снова вставьте/выберите файл.

Для изображений из буфера:

- убедитесь, что в буфере есть bitmap, а не только имя файла или URL браузера;
- проверьте, что terminal host не перехватывает `Ctrl+V` до DEcode;
- в Wayland установите `wl-clipboard`, в X11 — `xclip`;
- используйте браузер `@` как детерминированный запасной способ.

Браузер `@` открывает workspace, домашний каталог, Рабочий стол, Загрузки, родительские каталоги и корни/диски. `Space` отмечает несколько файлов. Внешние и временные файлы копируются в хранилище сессии до запроса.

## Drag and drop ничего не делает

Перетаскивание реализуется terminal emulator по-разному. DEcode принимает текст абсолютного пути, который создаёт совместимый терминал, но не может заставить host terminal сгенерировать drop event. Попробуйте:

1. перетащить файл в composer и проверить появление attachment chips;
2. вставить абсолютный путь;
3. выбрать файл напрямую через `@`.

Пути с пробелами заключайте в кавычки, если терминал вставляет обычный текст. За одну вставку можно прикрепить несколько абсолютных путей в кавычках.

## Файл отклонён или модель не может его прочитать

Проверьте имя, определённый тип, размер, суммарный размер хода и возможности провайдера. DEcode умеет хранить и маршрутизировать изображения, документы, текст, аудио и видео, но не каждая модель принимает каждый тип. Стандартные пределы: 16 файлов, 50 МиБ на файл и 50 МиБ на ход.

Зашифрованный, повреждённый, неподдерживаемый или переименованный с неверным расширением файл всё равно может быть отклонён. DEcode не обещает качество смыслового разбора формата, который провайдер не умеет обрабатывать.

## Пауза, продолжение или отмена работают неожиданно

`F6` ставит ход агента на паузу и продолжает его; `F8` отменяет приостановленный ход. Продолжение создаёт новый запрос к провайдеру от последней durable-границы. Итоги времени, токенов и стоимости относятся ко всему логическому ходу и включают завершённую работу до паузы.

Внешняя команда может успеть завершиться между запросом отмены и остановкой процесса. Если DEcode не может доказать её эффект, он записывает unknown/recovery state, а не предполагает успех и не повторяет действие. Перед повтором потенциально разрушительной операции проверьте Git diff и процессы.

## Команды не работают, хотя выполняются в другом shell

Команды модели запускаются неинтерактивно, с null stdin, и могут использовать другой настроенный shell или `PATH`. Проверьте:

- наличие файла через `where.exe` в Windows или `command -v` в Unix;
- quoting и разделители конкретного shell;
- рабочий каталог;
- окружение, унаследованное процессом DEcode;
- timeout и лимит вывода;
- отказ approval или sandbox в карточке инструмента.

В Windows команда `python` может отсутствовать при наличии `py -3`. Синтаксис PowerShell нельзя считать совместимым с CMD и наоборот.

## Неверные мышь, цвета или раскладка

Используйте актуальный терминал с UTF-8 и цветом, затем увеличьте окно выше минимального рабочего размера. Проверьте, не перехватывает ли terminal или multiplexer mouse reporting. Сравните запуск без SSH/tmux и с распространённым `TERM`, например `xterm-256color`.

У каждого действия есть клавиатурный путь. Если видимый активный элемент не нажимается мышью, но работает через фокус и `Enter`, запишите название и версию терминала, размер окна, ОС, locale, theme и точный экран.

## Ошибка сборки

Обновите стабильный toolchain и проверьте зафиксированный граф зависимостей:

```bash
rustup update stable
cargo clean
cargo check --locked --all-targets
```

В Windows ошибка linker обычно означает отсутствие MSVC C++ build tools или Windows SDK. В Linux установите C toolchain своего дистрибутива. Сетевые ошибки загрузки crates не относятся к ошибкам компилятора; не удаляйте `Cargo.lock`, чтобы их скрыть.

## Сбор безопасной диагностики

Запишите:

```text
decode --help
rustc --version
cargo --version
git rev-parse --short HEAD
```

Также укажите ОС, terminal/version, размеры терминала, провайдера и модель без секретов, точные шаги, ожидаемое поведение и очищенную ошибку. Файловый tracing настраивается через `[logging]` либо `--log-level`/`--log-dir`; DEcode намеренно не пишет диагностические логи TUI в stdout.

Сначала найдите похожие issue, затем используйте bug form репозитория. Эксплуатируемые уязвимости отправляйте приватно по [политике безопасности](../SECURITY.md).
