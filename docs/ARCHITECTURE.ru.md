# Архитектура DEcode

[English](ARCHITECTURE.md) · [Документация](README.ru.md) · [Безопасность](SECURITY.ru.md) · [Участие в разработке](../CONTRIBUTING.ru.md)

Это карта владения runtime, границ доверия и durable-состояния, а также ожидаемого порядка межмодульных изменений. Прочитайте её перед изменением оркестрации, provider adapters, инструментов, persistence или состояния UI.

## Цели архитектуры

DEcode построен вокруг пяти инвариантов:

1. изменяемым состоянием агента владеет один actor;
2. UI отображает snapshots и отправляет типизированные намерения, но не выполняет бизнес-операции;
3. данные модели и репозитория никогда не становятся полномочиями пользователя;
4. потоковая и внешняя работа становится durable только на явных причинных границах;
5. каждый неограниченный внешний ресурс получает пределы количества, байтов, времени и отмену.

## Обзор runtime

```text
клавиатура / мышь / вставка
            |
            v
      состояние TUI ---- typed OrchestratorCommand -------+
            ^                                             |
            |                                             v
 snapshots / events <---- agent::orchestrator <---- поток провайдера
                              |   |   |
                              |   |   +---- MCP / LSP / индекс / плагины
                              |   +-------- tools / approvals / checkpoints
                              +------------ история / сессии / субагенты
```

`agent::orchestrator` — единственный координирующий actor. Он владеет API-вызовами, причинной историей, инструментами, persistence сессий, checkpoints, субагентами, runtime MCP/LSP, индексом репозитория, плагинами и snapshots UI. Обычные запросы идут через ограниченную очередь. Interrupt, reset, pause и whip используют отдельный объединяющий канал управления, поэтому заполненная очередь не может удалить срочный сигнал.

| `code_index` | Инкрементальный lexical/symbol index и необязательные ограниченные remote embeddings |
| `plugins` | Проверка manifest/marketplace/digest и атомарная материализация пакета |
| `ui` | Ratatui widgets, registries фокуса/кликов и безопасный рендер immutable snapshots |
| `terminal` | Жизненный цикл пользовательского PTY/ConPTY отдельно от команд модели |

## Жизненный цикл логического хода

1. Проверить composer и скопировать вложения в хранилище сессии.
2. Добавить пользовательский ввод в логическую историю и собрать ограниченный provider request.
3. Закодировать запрос через выбранный provider adapter.
4. Передавать deltas в косметический live preview и полный буфер ответа.
5. Отклонить оборванный или ошибочный stream до авторитетного parsing.
6. Извлечь полные native function calls или полные legacy tool envelopes.
7. Применить ограничения режима, privacy policy, approval policy и lifecycle hooks.
8. Выполнить tools с отменой, timeout, byte limits, panic containment и атомарной мутацией.
9. Записать точные результаты и replay-safe непрозрачные provider items в durable history.
10. Продолжать до ответа без tool calls либо вернуть управление пользователю на iteration boundary.

Live preview никогда не является авторитетным. Частично показанный вызов инструмента не может выполниться, пока ход провайдера не завершён и не проверен.

## Граница провайдера

Все adapters получают одинаковые внутренние conversation и capability description. Каждый adapter отвечает за собственные:

- проверку endpoint и авторизации;
- сериализацию запроса;
- отображение возможностей вложений;
- нормализацию stream events;
- извлечение usage токенов;
- классификацию retry и безопасные ошибки.

Responses, Chat Completions, Anthropic Messages, Gemini Content и Bedrock Runtime не считаются взаимозаменяемыми wire formats. Смена провайдера меняет сериализацию и авторизацию, но не полномочия файловой системы или shell.

## История, контекст и сжатие

`agent::state` отделяет суммарный usage от ограниченного input, восстановленного для следующего запроса. Сжатие контекста детерминировано и сохраняет причинность:

- сохраняется начальная задача;
- сохраняется новейшая полная группа user/assistant/tool;
- старый восстанавливаемый вывод инструментов сокращается раньше смысла диалога;
- в историю добавляется видимое событие сжатия;
- если обязательная новейшая группа не помещается, система отказывает безопасно.

Stateful-провайдер может хранить provider response identifier, но локальный журнал остаётся источником восстановления. Stateless-режим всегда восстанавливает ограниченный запрос из локального состояния.

## Инструменты и граница файловой системы

Выбранные моделью пути разрешаются относительно workspace capability root. Traversal, выход абсолютного пути, symlink/junction/reparse escape, запрещённый privacy путь и replacement race завершаются отказом. Чтение и поиск ограничены. Запись использует точные патчи либо временный файл в том же каталоге с последующим атомарным persist.

Команды получают фиксированный рабочий каталог, null stdin, ограничения времени и вывода, отмену, очистку дерева процессов и независимое подтверждение. Пользовательская вкладка Terminal не создаёт обход auto-approval для команд модели.

## Вложения

Запись вложения в журнале содержит безопасное имя, определённый тип, MIME, размер, SHA-256, detail mode и ссылку на blob сессии. После загрузки она не зависит от исходного пути Temp, Загрузок или буфера.

Перед каждым provider request DEcode снова открывает blob, проверяет размер и digest и преобразует его в нативную часть выбранного провайдера. Capability checks отклоняют неподдерживаемое изображение, документ, аудио или видео до HTTP-запроса.

## Persistence и восстановление

История сессии хранится в checksummed append-only JSONL. Flush/fsync и восстановление torn tail защищают подтверждённые границы, а периодическое сжатие атомарно записывает замену. Durable record различает completed, failed, paused, cancelled и unknown-effect операции.

Пауза отменяет активную работу и записывает последнюю подтверждённую причинную границу. Продолжение создаёт новый запрос от этой границы и не имитирует продолжение закрытого сетевого stream. Rewind восстанавливает только изменения, отнесённые к checkpoint, и отказывается затирать конфликтующие ручные правки.

## Субагенты

Research agents ограничены read-only capability. Writer agents работают в иерархических отдельных Git worktrees. Scheduler проверяет DAG-зависимости, file claims, глубину, fan-out, параллельность, iterations, wall time, output, токены агента и всей ветки.

Вложенный writer интегрируется в writer-предка только после review. Durable acknowledgements и unknown-effect recovery не позволяют считать прерванную работу завершённой. Доступ субагентов к MCP включается отдельно и повторно применяет permissions сервера.

## Архитектура UI

UI читает immutable/coalesced snapshots и отправляет typed commands. `FocusManager` и registries click regions связывают мышь и клавиатуру с одним действием. Обрезанный или disabled control не должен сохранять активную область клика.

Текст провайдера, tool, процесса, файла, MCP, LSP и плагина очищается до layout или syntax highlighting. Pixel, анимированная `D`, таймеры и ETA — производное presentation state, которое не меняет поведение агента.

## Иерархия доверия

От высшего уровня полномочий к низшему:

1. скомпилированные safety invariants;
2. явные CLI и process environment локального пользователя;
3. явная или системная пользовательская конфигурация вне workspace;
4. ограниченная проектная конфигурация и инструкции репозитория;
5. вывод модели, файлы, вывод tool/process, данные MCP/LSP и удалённые ответы.

Низший уровень может сузить поведение, но не может выбрать секреты, provider endpoints, исполняемые hooks или расширенные разрешения.

## Карта persistence

| Данные | Правило размещения |
|---|---|
| Пользовательская конфигурация | Системный config directory или явный `--config` |
| Секреты провайдера/OAuth | Process environment, явный env file или OS keyring |
| Журнал и metadata сессий | `agent.session_dir` либо системный data directory |
| Blobs вложений | Content-addressed store рядом с данными сессии |
| Checkpoints и WAL субагентов | Приватные данные вне обычных исходных файлов |
| Writer worktrees | Настроенный корневой каталог worktrees субагентов |
| Индекс и cache embeddings | Cache с ключом workspace/privacy/model в приватных данных |
| Плагины и пользовательские connections | Системные data/config stores |
| Структурированные логи | Явный каталог логов, никогда не stdout TUI |

## Добавление или изменение функции

Для каждого внешнего, привилегированного или изменяющего пути:

1. определите типизированные config, command, outcome и error;
2. определите уровень доверия источника и запретите overrides снизу;
3. задайте пределы количества, байтов, времени, retry и iterations;
4. сделайте отмену наблюдаемой до необратимого commit;
5. оставьте файловые операции capability-relative и privacy-filtered;
6. сохраняйте replay-safe state на явной durable-границе;
7. добавьте мышь и клавиатуру для каждого видимого действия;
8. очищайте недоверенный текст до styling;
9. тестируйте success, denial, timeout, cancellation, duplicate input, torn state и recovery;
10. обновляйте английскую и русскую документацию и все переводы UI.

Перед pull request запустите полный набор проверок из [CONTRIBUTING.ru.md](../CONTRIBUTING.ru.md).
